# Signals and change lists replace tree walks and table scans

Every poll used to traverse the whole non-quiescent tree, and every barrier scanned the whole group table several times and walked the tree again for liveness, roots, announcement and streams. That is cheap while there are few barriers, but a `@stream` under a list makes the number of barriers grow with the list, so total barrier work grew with its square (issue 23: 10k parents took 138 ms and 40k took 2 s). Work is now driven by what changed. Each scope owns a signal, a set of flags raised on it and every ancestor: its field futures and stream sources wake through it, so a poll descends only into flagged scopes; settling raises it where objects were decided, and stream drivers raise it when a turn, an ended source or a halt needs the barrier, so the barrier walks only flagged subtrees. The group table records its own changes: every state write goes through one method that keeps an open-group count and lists what was announced, died, halted or may be reclaimed; each group counts the holds of unfinished work that delivers under it, and a group is examined for completion only when it is released, its last hold goes, a group it waits on finishes, or a set it shares settles. Groups link to their dependents, so a death settles its own subtree, and scopes know their path, so a fragment's roots and the objects carrying its nested groups are reached directly.

## Considered options

- Local indexes only (a parent index per stream range, completion checks per touched parent): removed about half the time, but left every scan over the group table and the tree, so the shape stayed quadratic.
- Dirty sets consumed by the barrier without touching polling: the same change lists, but every poll would still traverse the tree, and the spec already named polling as the obvious next step.
- A ready queue of scopes identified by a flat id: scopes have no identity outside their nested frames (ADR 0006), so a queue needs either stored paths per scope or unsafe pointers; the signal chain reaches a scope the way the tree already does, at depth cost per wake, and depth is fixed by the document (ADR 0005).
- Announcing from the children of each shipped group through their carriers: proportional for fragments, but a stream group has one child per item and ships one range at a time, so items decided by the range that shipped them are what announcement follows, with carriers only for nested fragments whose object was decided earlier.
- Letting candidate order depend on the queue: the output must not depend on internal order, so examination keeps the scan's order (shared sets by id, then fragments by wire id), a group queued mid-pass joins the pass only where a scan would still reach it, and the sweep replays the scan's slot order so group ids are unchanged.

## Consequences

Barrier and poll cost follow what changed; the `streams` workload scales linearly (10k parents 23 ms and 40k 93 ms, from 138 ms and 1972 ms), the property suite runs nine times faster, and output is byte-identical to before on every compliance workload. Each group carries about 80 bytes more (dependents, holds, carrier, flags), each scope an `Arc` signal and its path, and each stream driver a per-object parent index. Every place that changes what a group or scope can do must say so: a new hold, event or state write that bypasses `Groups::set_state`, the signals or the hold counts would leave work unexamined, which the property suite's stall assertion and regression seeds catch. Shipping a fragment no longer allocates for its own sake: wire ids are numbers formatted at serialization, group paths are shared, roots are borrowed from the registry, and the error sink and the alive-marking stack are reused across one barrier's entries (the `deferred` workload: 13 allocations fewer per fragment). The work counters in `__private` and the `work` compliance test keep the per-barrier cost from growing with the list again.
